03 / Evidence before edits

RPI: turn a question into verified work

HVE Core on GitHub: Research → Plan → Implement, with review and follow-up.

R

Research

Understand before editing

  • Inspect data contracts and code.
  • Check leakage and alternatives.
  • Separate evidence from assumptions.

Output: findings + open decisions

/rpi-research
P

Plan

Make success testable

  • Choose the split and metrics.
  • Sequence small, bounded tasks.
  • Define tests and acceptance criteria.

Output: plan + critique

/rpi-plan
I

Implement

Execute the approved scope

  • Build the pipeline and tests.
  • Run checks; record real results.
  • Review diffs against the plan.

Output: changes + validation

/rpi-implement

05 / A bounded experiment

Try it: a reproducible credit-risk baseline

One synthetic dataset. One clear objective. Three bounded prompts.

01
RESEARCH / ASK
Inspect this synthetic dataset and notebook. Identify leakage risks and compare validation splits. Do not edit files yet.
02
PLAN / HVE RPI
Plan a reproducible baseline with a time-based split. Fit preprocessing on training data only. Define metrics and tests before coding.
03
IMPLEMENT / AGENT
Implement the approved plan and run the tests. Report PR-AUC, calibration and subgroup results. Show the diff and any remaining limitations.

Done means

  • A clean rerun works.
  • Split and leakage tests pass.
  • Metrics include limitations.
  • A human reviews the result.

Faster work. Same rigor.

Banking guardrail: synthetic or approved de-identified data only; no client PII or secrets in prompts.

Presenter notes and sources

This is an educational workflow, not a production credit-model approval. Choose thresholds with the business before implementation. Account for label horizons, customer isolation and temporal gaps when the data requires them. Reserve the final holdout for final evaluation.

PR-AUC is not a complete decision criterion. Calibration, uncertainty and subgroup analysis need context; subgroup results do not establish fairness or compliance. A clean rerun uses documented dependencies and seeds and a fresh kernel/environment.

Customer policy governs approved data, providers, tool permissions and retention. De-identification requires approval and does not guarantee privacy. The large/medium/small mapping is a workshop recommendation, not an HVE requirement. Hydrafusion behavior and availability were not verified in public Copilot documentation.
